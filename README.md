# 영수증 여행기록 (receipt-book)

여행 중 받은 영수증을 찍어 올리면 날짜·가게·금액을 정리하고, **영수증에 적힌 주소로 지도에 핀을 찍어**
날짜별 동선(발자취)을 남기는 여행 기록장. 해외 영수증은 번역하고, 내가 환전한 환율로 원화를 계산한다.
빌드 없는 정적 웹앱(PWA). (2026-11 생활 가계부 유형 제거 → 여행 전용으로 컨셉 변경)

## 화면
| 탭 | 내용 |
|---|---|
| **발자취** (기본) | 지도(번호 핀 + 시간순 점선) · 일차 칩(전체/1일차/2일차…) · 날짜별 일정 타임라인 · 지출/발자취 수/이동거리(직선) |
| 경비 | **여행 경비 정리**(총액·하루 평균·1인당·카드/현금·환전·남은 현금·사람별 부담, 메신저용 복사) + 카테고리·일별·도시별·많이 쓴 곳·통화별 |
| 환전 | 가중평균 환율, 남은 현금, **환전 캡처 자동 등록**, 직접 추가 (외화를 고른 여행만) |
| 정산 | 일행 N빵·최소 송금 (일행 2명 이상만) |
| 관리 | CSV(주소·위도·경도 포함), 여행 정보 수정·삭제 |

국내 여행은 외화를 비워 두면 된다(원화만, 원문·환산 칸 숨김). 예전 생활 가계부 데이터는 국내 여행으로 열린다.

## 위치를 찾는 순서 (`geo.js`)
Gemini가 영수증에서 `address`(원문), `map_query`(짧은 검색어), `city`, `country`를 함께 뽑고,
OpenStreetMap **Nominatim**으로 좌표를 찾는다. 앞에서 찾으면 멈춘다.
1. map_query → 2. 주소 원문 → 3. 건물·층 표시를 뗀 주소 → 4. 끝 번지를 한 토막씩 뗀 주소(최대 4번, 동네 수준이면 "대략")
5. 상호 + 도시 → 6. 사진 GPS(EXIF, 원본 사진에 있을 때) → 7. 도시만("대략")

- 상호 검색을 뒤로 둔 이유: 체인점은 다른 지점이 먼저 걸린다(실측: くら寿司 なんば店 → 7km 떨어진 지점).
- 일본 주소는 Nominatim이 번지까지 못 찾는 일이 많아 丁目 수준까지 깎는다(실측: 梅田1-1 ✗ → 梅田1 ✓).
- 사진 GPS가 주소보다 뒤인 이유: 영수증을 숙소에서 모아 찍으면 전부 숙소로 찍힌다.
- 수정 화면에서 **지도 탭으로 직접 지정 / 장소 검색 / 지금 내 위치 / 주소로 다시 찾기**가 된다. 직접 정한 위치는 다시 인식해도 유지.
- Nominatim 정책(초당 1회·캐시·대량 금지)에 맞춰 1.1초 간격 줄 세우기 + localStorage 캐시. **개인용 규모 전제** — 공개 서비스로 키우면 유료 지오코더로 바꿔야 한다.

## 지도 (`map.js`)
외부 라이브러리 없이 OSM 타일을 직접 그린다(끌기·휠·더블클릭·두 손가락 확대·핀 탭). 미리보기 창이 외부 script를
못 붙이고 빌드 도구도 없어서. 타일이 안 오면 회색 바탕에 핀·동선만 보인다. 출처 표기 `© OpenStreetMap` 상시 노출
(OSM 이용 조건 — 데이터 ODbL, 타일 서버 이용 정책 준수 필요. 사용량이 커지면 타일 제공자를 바꿀 것).

## 영수증 인식 흐름
1. 영수증 찍기 / 앨범에서(여러 장) / 직접 입력
2. Gemini 1회 호출 → 날짜·시각·상호(원문+한국어)·통화·항목(원문+번역)·세금·할인·합계·결제수단·카테고리·**주소·도시·국가**
3. 확인·수정 화면을 항상 거침. 위치 찾기는 뒤에서 비동기로 돌고, 저장 뒤에 끝나도 그 기록에 반영된다
4. 키가 없거나 인식 실패 → 직접 입력(사진 GPS가 있으면 위치는 자동)

**환전 캡처 등록**(환전 탭): 은행 앱 환전 완료 화면·트래블카드 충전 내역·환전 영수증 → 여러 건 추출, 100단위 환율 보정, 중복 표시.

## 파일
- `store.js` IndexedDB(여행·지출·환전·사진). 못 열면 메모리 모드 + 경고 배너
- `scan.js` 사진 압축 + Gemini 호출(생 fetch, `responseSchema`) + 정규화·합계 검증
- `geo.js` 지오코딩·EXIF GPS·거리·날짜별 묶음 / `map.js` 타일 지도
- `fx.js` 환율·남은 현금 / `settle.js` 정산 / `stats.js` 집계·차트 / `csv.js` CSV·JSON 백업
- `app.js` 해시 라우팅 화면 / `sw.js` 네트워크 우선 서비스워커(외부 오리진은 캐시 안 함)
- `config.js` 공용 인식 서버 주소(비밀값 아님) / `proxy/worker.js` Cloudflare 중계 서버

## 개인정보
- 사진은 인식할 때만 Google Gemini로 전송(무료 키는 학습에 쓰일 수 있음 — 설정 화면에 고지)
- 위치 찾기 때 **가게 주소·상호 텍스트**가 OpenStreetMap Nominatim으로 전송(사진은 아님). 지도 타일도 OSM에서 받음
- "지금 내 위치"를 누를 때만 기기 위치 권한을 요청

### 공용 인식 서버 (운영자 키로 모두가 쓰기)
공개 저장소 코드에 키를 넣으면 누구나 볼 수 있으므로, 키는 Cloudflare Worker(`proxy/worker.js`)에만 둔다.
앱은 `config.js`의 `proxyUrl`로 요청하고, 사용자가 설정에 자기 키를 넣으면 그 키로 직접 부른다.

1. Cloudflare 가입 → **Workers & Pages → Create → Worker**(Hello World로 시작) → 이름 예: `receipt-trip` → Deploy
2. **Edit code** → 기존 코드를 지우고 `proxy/worker.js` 내용을 붙여넣기 → Deploy
3. 그 Worker의 **Settings → Variables and Secrets → Add** → Type `Secret`, Name `GEMINI_KEY`, Value에 Gemini 키 → Deploy
4. 나온 주소`https://receipt-trip.jugga1004.workers.dev` — `config.js`에 이미 들어 있다(Worker 이름을 다르게 지으면 여기를 고친다)

**실행 지역 고정(필수)**: 무료 요금제는 한국 사용자를 홍콩(HKG) 데이터센터로 보내고, Gemini는 홍콩발 요청을
"User location is not supported"로 거절한다(2026-11 실측, 3회 연속). 저장소 맨 위 `wrangler.toml`(main = `proxy/worker.js`)의 `placement.region = "gcp:us-central1"`로
미국에서 실행되게 한다. 대시보드에는 리전 지정이 없으므로(Smart만 있음) Worker 설정 → 빌드 → **Git 저장소 연결**
(저장소 `receipt-trip`, 루트 디렉터리는 비워 둠)로 이 파일을 써서 배포한다. 설정 파일이 `proxy/` 안에만 있으면 Cloudflare가 저장소 전체를 정적 사이트로 올려 버린다(실측). 앱은 이 경우를 451로 받아 두 번까지 다시 시도한다.

막아 둔 것: `jugga1004.github.io`에서 온 요청만, flash 계열 모델만, 4MB 이하, IP당 분당 15회(대략).
Origin은 브라우저 밖에선 꾸밀 수 있으므로 **Google 쪽 하루 요청 상한도 같이 걸어 둘 것**(Google Cloud 콘솔 → Generative Language API → 할당량).
무료 키면 모든 사용자가 무료 한도를 나눠 쓰고, 보낸 영수증은 Google이 학습에 쓸 수 있다(설정 화면에 고지).
결제를 켠 키면 사용량만큼 요금이 운영자에게 나온다.
